# 文档漂移检测

## ⛔ 时序要求：先展示 → 再改码 → 后检测

当用户要求修改项目源码文件时（非测试/配置/文档），**必须按以下顺序执行，不得跳步**：

### 前置判断（每次都做）

1. 读取 `seedpacespec/config.yaml` → 若 `driftDetection.enabled` 不为 `true`（包括字段不存在、文件不存在）→ **停止，不做任何检测，也不要读取检测规范文件**
2. 若本次修改是由 sdx skill（如 sdx-apply）正在驱动执行的步骤 → 停止（sdx skill 内部已有偏离检测）

### Phase 1：前置设计上下文展示（改代码前 ⛔ 必须先于任何文件写入）

**在 Edit/Write 任何源码文件之前**，执行以下步骤：

1. 从用户描述推断即将修改的文件路径
2. 扫描 `seedpacespec/changes/active-change/` 找到聚焦变更
3. 读取聚焦变更的 `design.md`（文件树章节）和 `trds/*.md`，做路径匹配
4. **命中** → 输出以下格式，然后开始修改：

```
📋 设计上下文

本次要修改的文件在活跃变更「{变更名}」中有对应设计：

  - {文件路径}
    └─ TRD: trds/{trd文件}.md → §{章节标题}（第 {N} 行）
    └─ Design: design.md → {所属模块节}（第 {N} 行）

你可以先查看设计意图再决定如何修改。
```

5. **未命中** → 不展示，直接修改

> 展示不阻塞——输出后立即开始修改，不等待用户确认。

### Phase 2：漂移检测（改代码后）

代码修改完成后 → 读取 `.claude/skills/_shared/doc-drift-awareness.md` 的「检测流程（改代码后）」章节并执行。
